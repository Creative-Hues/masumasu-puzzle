# フェーズ1(土台)の計画

創の確認ずみ。質問への答えは、いちばん下の「8. 質問への答え」にまとめた。答えと本文が食い違うところは、答えのほうに従う。

## 目的

4つのパズルに共通する「入れ物」を先に作る。パズルの中身がなくても、最初の画面からステージを選び、ヒントを使い、クリアの帯が出て、設定と保存が効き、ホーム画面に追加してオフラインで開ける、というところまでを動く形にする。フェーズ2以降は、パズルの中身を1つずつ差し込むだけで済むようにする。

## 1. 使う技術の提案

| 項目 | 提案 | 理由 |
| --- | --- | --- |
| 作り方 | **フレームワーク(作るための大きな道具)なし。ふつうのHTML・CSS・JavaScript** | 試作もこの形なので移しやすい。道具の更新に振り回されない |
| ファイルの分け方 | JavaScriptを「モジュール」(役割ごとの小さなファイル)に分け、`import` で読み込む | 共通部分を1か所にまとめ、各パズルから使える |
| ビルド(公開前の変換作業) | **なし**。書いたファイルをそのまま公開する | Cloudflare Pagesの設定が「そのまま出す」だけで済む |
| オフライン | Service Worker(ネットがなくても開けるよう、ファイルを端末にしまっておく仕組み)を手で書く | 中身が単純なので道具は要らない |
| 問題作りの裏側 | Web Worker(画面を止めずに裏で計算する仕組み)。フェーズ1では入れ口だけ用意し、よつつじ(フェーズ5)で使う | 計画書どおり |
| 自動の確かめ | Node.js(PCに入っている。v24)に付いている `node --test` で、乱数・段階・保存などの計算を確かめる | 追加の道具なしで動く |
| PCでの確認用サーバー | `npx serve public`(その場でファイルを配る小さな道具。公開するフォルダだけを配る) | PCに入れっぱなしにしなくてよい |

## 2. ファイル構成の提案

```
masumasu-puzzle/
├─ public/                    公開するのはこのフォルダの中だけ
│  ├─ index.html              1ページだけ。画面は中身を入れ替えて切り替える
│  ├─ manifest.webmanifest    ホーム画面に追加するときの名前・アイコン・色
│  ├─ sw.js                   オフライン用(Service Worker)
│  ├─ _headers                Cloudflare Pagesに「sw.jsは毎回新しく読む」と伝える
│  ├─ icons/                  アイコンB(icon.svg と、各大きさのPNG)
│  ├─ css/
│  │  ├─ base.css             色の決まり(明るい・暗い)、文字、ボタン
│  │  └─ screens.css          各画面の並べ方、クリアの帯
│  └─ js/
│     ├─ app.js               起動と画面の切り替え(URLの # のあとで場所を覚える)
│     ├─ core/                画面を持たない共通の計算
│     │  ├─ rng.js            ステージ番号から乱数を作る(試作と同じ mulberry32)
│     │  ├─ stages.js         何段階目か(1〜20が1段階目、21〜40が2段階目…)
│     │  ├─ palettes.js       くすみ系5種類(計画書の表の色)、ステージごとの切り替え
│     │  ├─ storage.js        端末への保存(進み具合・設定)
│     │  ├─ sound.js          木の音をその場で作る
│     │  └─ haptics.js        触感
│     ├─ ui/                  共通の画面
│     │  ├─ home.js           最初の画面
│     │  ├─ play.js           遊ぶ画面の枠(上の情報・3つのボタン・ルール・ヒント回数・帯)
│     │  ├─ stage-list.js     一覧(番号のマス目)
│     │  └─ settings.js       設定画面
│     └─ puzzles/
│        ├─ registry.js       4つのパズルの登録表(名前・ひとこと説明・中身の場所)
│        └─ trial/            確かめ用の仮パズル(下の5で説明)
│           (フェーズ2以降に majikiri/ nobishiro/ utsushie/ yotsutsuji/ を足す)
├─ tools/make-icons.mjs       アイコンのPNGを作って public/icons/ に置く小さな道具(追加の部品なし)
├─ tests/                     node --test で動かす確かめ(public/ の中のコードを確かめる)
├─ package.json               確かめ・PCでの確認の命令をまとめたもの(公開しない)
└─ docs/                      計画書・試作(公開しない)
```

### パズルを差し込む「約束事」

各パズルは、共通の枠に次のものを渡すだけにする。枠のほう(ステージ・ヒント回数・帯・音・保存)は4つで同じものを使う。

- `name`・`tagline`・`rules`(名前、ひとこと説明、ルール説明の文)
- `describe(stage)`：盤面の中身の文字(例「6×6・縦2本・横2本」)
- `start(stage, 盤面の場所, 枠からの道具)`：盤面を作って表示する。枠からの道具は「乱数」「その回の8色」「音を鳴らす」「震わせる」「進み具合の文字を変える」「一言を出す」「クリアした」の知らせ
- 盤面側が持つ操作：`undo()`(1手戻す)、`reset()`(最初から)、`hint()`(間違った手を戻し、次の場所を1つ光らせる)、`glow()`(クリアの光り方。終わったら枠に知らせる)

ヒントの「3回まで」「使い切ったら飛ばす」は枠側で数える。中身は「戻して光らせる」ことだけを受け持つ。

## 3. 作るもの(計画書「作る順番」の1)

### 最初の画面
- アプリ名「ますます」と、4つのパズル(のびしろ・まじきり・よつつじ・うつしえ の順。計画書の表の順)を並べる。
- それぞれ名前とひとこと説明(「色を伸ばす。」など)。小さな絵の場所はフェーズ6まで空けない(入れるときに足す)。
- 右上に「設定」。

### 遊ぶ画面の枠
- 上：「もどる」(最初の画面へ)、◀ ステージN ▶、「一覧」。その下に盤面の中身・進み具合・ヒントの残り。
- 真ん中：盤面(中身は各パズル)。
- 下：「1手戻す」「最初から」「ヒント」。その下にルールの説明。
- ◀は1より前に行けない。▶は「まだクリアしていない次のステージ」より先に行けない(1本道)。

### ステージの仕組み
- 乱数は「パズルの種類＋ステージ番号」から作り、同じ番号はいつも同じ問題になる。
- 20ステージごとの段階は `stages.js` で計算し、各パズルが段階ごとの盤面の大きさを決める。
- 一覧：1から「次に遊べるステージ」まで番号をマス目に並べる。クリアしたものは色を変え、今のステージに枠をつける。開くと今のステージが見える位置まで動く(試作と同じ)。

### ヒントと「このステージを飛ばす」
- ヒントを押すと、盤面側の `hint()` を呼び、残りを1減らす。上の「ヒント残り」が変わる。
- 3回使い切ると「このステージを飛ばす」が出る。押すとクリア扱いにして保存し、次のステージへ進めるようにする(帯の出し方は質問2)。

### クリアの帯
- 盤面側の光り方が終わったら、下から帯がせり上がり、「クリア。」と「次へ」を出す。紙吹雪などの飾りはなし。
- 動きを減らす設定の端末では、すっと出るだけにする。

### 配色と明るい・暗い画面
- 5種類(秋の山・古い喫茶店・古本屋・あじさいの小道・砂浜)を、ステージ1から表の順に切り替える(6で秋の山に戻る)。テーマの名前は画面に出さない。
- 下地や文字の色は、のびしろの試作の「すっきり無地」の色をもとにする。明るい画面・暗い画面の両方を用意する。
- 「スマホに合わせる」のときは端末の設定に従い、途中で切り替えてもすぐ変わる。

### 設定画面
- 効果音(オン・オフ)、触感(オン・オフ)、画面の明るさ(スマホに合わせる・明るい・暗い)。
- 変えるとその場で効き、端末に保存する。
- 書き出し・読み込み(バックアップ)は計画書ではフェーズ6なので、ここでは作らない。ただし保存の形は、あとで書き出しやすいように1か所にまとめておく。

### 効果音(木の音)
- 音のファイルは使わず、Web Audio(ブラウザで音を作る仕組み)で、短い雑音を木の響きの高さにしぼり、すぐ消える音を作る。
- 4種類：置く・引く(コトッ)、ボタン(軽いカタッ)、クリア(木琴のように3つ上がる)、間違い(低く鈍いコトコト)。
- iPhoneは、画面に初めて触れたときに音の準備をする決まりがあるので、最初のタップで準備する。

### 触感
- Android：`navigator.vibrate`(震わせる命令)。
- iPhone：見えない「スイッチ部品」を置き、それを押したことにして触感を借りる(のびしろの試作と同じ方法。iOS 18以降)。指で触れた瞬間にしか効かないことがある。将来使えなくなる可能性あり(計画書のとおり)。

### 保存
- 端末の中(localStorage)に、1つの入れ物としてまとめて保存する。中身：設定と、パズルごとの「どこまでクリアしたか」「今のステージ」。
- 保存の形に版の番号をつけ、あとで形を変えても古いデータを読めるようにする。
- iPhoneで消えにくくするよう、ブラウザに「消さないで」とお願いする(`navigator.storage.persist`)。

### ホーム画面への追加(PWA)とアイコンB
- アイコンB：白地に、すき間をあけた2×2のマス。左上 #b5838d・右上 #e5989b・左下 #8e9aaf・右下 #a3b18a(アイコン案のページと同じ並び。余白・すき間・角の丸みの比率も合わせる)。
- iPhoneは自分で角を丸めるので、PNGは角を丸めない正方形で作る。180px(iPhone用)、192px・512px(Android用)。`tools/make-icons.mjs` で作り、作ったPNGも一緒に置く。
- 名前は「ますます」。ホーム画面から開くと、アドレス欄のない全画面で開く。
- 全ファイルを端末にしまい、機内モードでも開けるようにする。新しい版を公開したら、次に開いたときに入れ替わる。

### 公開の手順(創がする所と、Claude Codeがする所)
1. 創：GitHubで Creative-Hues に masumasu-puzzle という空のリポジトリ(ファイル置き場)を作る。
2. Claude Code：このフォルダをgitで管理し始め、最初の記録(コミット)を作り、GitHubへ送る(送るときに一度、ブラウザでGitHubへのログインを求められる)。
3. 創：Cloudflareの管理画面で「Workers & Pages」→ 作成 → Pages → 「Gitにつなぐ」→ masumasu-puzzle を選ぶ。プロジェクト名は masumasu-puzzle、ビルドの命令は空、出すフォルダ(Build output directory)は `public`。これで docs/・tests/・tools/ は公開されない。
4. これで masumasu-puzzle.pages.dev に出る。以後はGitHubへ送るたびに自動で公開される。
   - main以外の枝(ブランチ)に送ると、確かめ用の別のURLができるので、本番に出す前にiPhoneで見られる。

## 5. パズルの中身がないときの確かめ方

**仮パズル(確かめ用)** を1つ作り、フェーズ1のあいだは4つのパズルどれを開いてもこれが出るようにする。中身が入ったパズルから順に、本物と入れ替える。全部入れ替わったら仮パズルは消す。

仮パズルの中身(共通部分を全部通るように作る)：
- ステージ番号の乱数で、盤面のいくつかのマスに印をつける。印のマスを全部タップしたらクリア。印のないマスをタップすると「間違い」(音と触感、一言)。
  → 同じ番号でいつも同じ盤面か、段階で盤面が大きくなるか、配色が切り替わるかが見て分かる。
- タップしたマスはその回の8色で塗る。→ 配色5種類の確認。
- ヒント：間違ったマスを戻し、次に押す印を1つ光らせる。→「戻して光らせる」と残り回数、3回後の「飛ばす」の確認。
- クリアで全マスが光り、そのあと帯。→ 帯と「次へ」、保存の確認。

自動の確かめ(`node --test`)：
- 同じステージ番号から同じ乱数が出る。
- 20・21・40・41・101 で段階が正しく変わる。
- ステージ1〜6で配色が表の順に回る。
- 保存：空の状態から始められる、壊れたデータでも止まらない、古い版のデータを読める。
- ヒント：3回で終わり、飛ばすとクリア扱いになる。

## 6. 動作確認の手順

### PC(Chrome)
1. masumasu-puzzle のフォルダで `npx serve public` を動かし、表示されたアドレスを開く。
2. 開発者ツール(F12)のスマホ表示で、iPhoneの大きさにして見る。
3. 4つのパズルを開き、◀▶・一覧・ヒント3回・飛ばす・クリアの帯・「次へ」を順に試す。
4. 設定で明るい・暗いを切り替え、再読み込みしても残るか見る。
5. 開発者ツールの「Application」でアイコンとmanifestを確かめ、「Network」の「Offline」にして再読み込みしても開くか見る。
6. `node --test` が全部通るか見る。

### iPhone(1台)
1. Safariで masumasu-puzzle.pages.dev を開く。
2. 共有ボタン →「ホーム画面に追加」。アイコンが白地に4色のマスになっているか。
3. ホーム画面から開く。アドレス欄がない全画面か。
4. どれかのパズルを開き、マスをタップ。木の音が鳴るか(消音スイッチは切っておく)、軽く震えるか。
5. ヒントを3回押し、「このステージを飛ばす」が出るか。飛ばすか解くかして、帯の「クリア。」「次へ」を見る。
6. ステージ2〜6へ進み、色の組み合わせが毎回変わるか。
7. 設定で効果音・触感をオフにして、鳴らない・震えないか。画面の明るさを「暗い」にして見る。コントロールセンターで端末を暗くし、「スマホに合わせる」で追いかけるか。
8. アプリを上にはらって完全に閉じ、もう一度開く。進んだステージが残っているか。
9. 機内モードにしてもう一度開く。ふつうに遊べるか。

## 7. 質問(実装の前に答えてほしいこと)

1. **文字の形**：試作は「Zen Maru Gothic」(ネットから読む丸い文字)を使っている。
   - 案A(おすすめ)：iPhoneに最初から入っている丸い文字(ヒラギノ丸ゴ)を使う。オフラインでも必ず同じ見た目で、読み込みも速い。PCやAndroidでは似た丸い文字か、ふつうの文字になる。
   - 案B：Zen Maru Gothicをネットから読み、一度読んだら端末にしまう。初めて開くときだけネットが要る。
2. **「このステージを飛ばす」の出し方**：ヒントを使い切ったら、「ヒント」のボタンが「このステージを飛ばす」に変わる形でよいか(おすすめ)。うっかり押さないよう、押したら「飛ばしますか」と一度聞くか。
3. **飛ばしたあと**：飛ばしたときも、盤面の光り方と「クリア。」の帯を出すか。それとも帯なしで、すぐ次のステージへ進むか。
4. **ヒントの残り回数**：ほかのステージへ移って戻ってきたら3回に戻るか(おすすめ。保存しないので単純)、使った回数を覚えておくか。
5. **一覧での見分け**：飛ばしたステージは、クリアしたステージと同じ見た目でよいか。
6. **途中の盤面**：アプリを閉じると、解きかけの盤面は最初からに戻る(計画書は「クリアしたステージと今のステージ」だけを保存する)。このままでよいか。
7. **ボタンなどの色**：ボタンや帯の「次へ」の色は、全ステージ同じ落ち着いた1色にするか(おすすめ)、その回の配色に合わせて変えるか。
8. **暗い画面での8色**：暗い画面でも、計画書の表と同じ8色をそのまま使ってよいか(くすみ系なので暗い下地でも見えると考えている)。
9. **公開の途中経過**：フェーズ1の公開では、4つのどれを開いても仮パズルが出る。母が見ても分かるよう「準備中」などの言葉を出すか、何も出さないか。
10. **GitHubとCloudflare**：リポジトリ Creative-Hues/masumasu-puzzle はもう作ってあるか。Cloudflareのアカウントはあるか。
11. **技術の提案**：上の「1. 使う技術の提案」(フレームワークなし・ビルドなし)で進めてよいか。
