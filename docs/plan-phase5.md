# フェーズ5(よつつじ)の計画

創の確認ずみ。質問への答えは、いちばん下の「14. 質問への答え」にまとめた。答えと本文が食い違うところは、答えのほうに従う。

## 目的

共通の枠に、よつつじの本物を差し込む。これで4つとも本物になるので、確かめ用の仮パズルは消す。仕様は docs/plan.md の「よつつじ」の節に従い、試作(docs/prototypes/yotsutsuji.html)の問題の作り方・なぞる操作・交差マスの描き方を土台に移す。試作の配色・文言・難易度・ヒントは使わない。ほかのパズルで決めたこと(色・震えない・ヒントの一言の形・確認などの間は受け付けない・1画面に収める・作り直さない)はそろえる。

## 1. ファイル

```
public/js/puzzles/yotsutsuji/
├─ logic.js       画面を持たない計算(難易度表・問題作り・答えの探し方・絵の具の混ぜ方・ヒント)
├─ worker.js      裏側(Web Worker)で問題を作る入れ口。logic.js を使う
└─ yotsutsuji.js  表示と操作(盤面の絵・なぞる・左の円のタップ・ヒントの光・クリアの光り方)
public/js/puzzles/trial/        消す(仮パズル)。仮パズル用の見た目(css)も消す
public/js/puzzles/registry.js   よつつじを本物に替え、仮パズルの読み込みを消す
public/sw.js                    オフライン用の一覧に3つ足し、仮パズルを消す
tests/yotsutsuji.test.mjs       問題作り・答えが1つか・ヒントの確かめ
```

## 2. 難易度表(docs/plan.md どおり)

| ステージ | 盤面 | 色 | 交差マス |
| --- | --- | --- | --- |
| 1〜20 | 5×5 | 2 | 1 |
| 21〜40 | 5×5 | 3 | 1 |
| 41〜60 | 6×6 | 3 | 1〜2 |
| 61〜80 | 6×6 | 4 | 1〜2 |
| 81〜100 | 7×7 | 4〜5 | 2〜3 |
| 101〜 | 8×8 | 5〜6 | 2〜3 |

- 「〜」の段階は、ステージごとに順番に入れ替える(ほかのパズルと同じ)。
- 色マスの多さ：序盤は多め。答えを1つに決めるのに必要な分に加えて、残りのマスの約30%を色マスにし、ステージごとに減らしてステージ61で0%にする(試作と同じ減り方。計画書の「ステージ60ごろには必要な分だけ」に合う)。
- 段階は共通の `tierOf()` で決める。

## 3. 問題の作り方(試作を移す)

1. 交差マスを、盤面の縁でない所に、となり合わないように置く。左の円・右の円の並ぶ行を選ぶ。
2. 先に答えの線を作る(試作の `genWithBridges`)。左右の円の並びが入れ替わるものだけ採用する。
3. 色マスを1つずつ足し、ほかの答えがないかを試作の探し方(`search`)で解いて確かめる。答えが1つに決まったら完成。そのあと序盤だけ色マスを足す。
- 乱数は、同じステージ番号ならいつも同じになるように、`stageRng('yotsutsuji', ステージ)` を使う(裏側でも同じ乱数を作れる)。
- 試作は、探す数の上限に達すると「答えが1つ」と確かめきれないまま出していた。上限に達したときは作り直し、答えが1つの問題だけを出す。ステージ1〜300を自動の確かめで作り、全部答えが1つか、1問を作る時間を確かめる。

## 4. 裏側で作る(Web Worker)

- 問題作りは `worker.js`(裏側)で行う。遊んでいるステージを出したら、すぐ次のステージを裏側で作っておく。
- 作った問題は覚えておき、◀▶で行き来してもすぐ出る。
- 裏側が使えない端末では、表で作る(試作と同じ)。
- まだできていないステージを開いたときの表示は質問7。

## 5. 画面

- **盤面**：試作と同じく1枚の絵(canvas)に描く。描き直すのは絵の中身だけ。暗い画面に切り替えたときや画面の大きさが変わったときも描き直す。盤面は横に少し長い(左右に円が並ぶ)ので、共通の枠の「盤面の縦横の比」を使う。
- **左の円**：その色で塗った円。**右の円**：グレー。線がつながると、その色になる。
- **色マス**：その色をうすく塗り、ふちを描く。
- **交差マス**：＋の印。縦と横に2色が通ると、2色を絵の具のように混ぜた色に変わる(試作の混ぜ方。その回の配色のまま混ぜる)。横の線が縦の線の上を通るように描く。
- **線の色**：その回の配色の8色を、上の円から順に使う(質問8)。
- **上の情報**：盤面の中身と進み具合の文は質問6。ヒント残りは枠が出す。
- **ルール説明の文**(docs/plan.md どおり)
  - 左の円からなぞって、右の円のどれかにつなぐ。
  - 線は、同じ色のマスを全部通る。
  - 線は交差しない。空白を残さず埋めたらクリア。
  - ＋のマスだけは交差できる。縦と横に、ちがう色の線を1本ずつまっすぐ通す。
  - 左の円をタップすると、その色の線が消える。

## 6. 操作(試作を移す)

| 操作 | どうなる |
| --- | --- |
| 左の円からなぞる | 線が伸びる。すでに線があれば引き直し |
| 線の先っぽからなぞる | 続きから伸ばせる |
| 来た道を戻る | 線が縮む |
| ほかの色のマス、ほかの線があるマスに入る | 止まる(線が伸びない) |
| 交差マスの中 | まっすぐしか進めない |
| 左の円をタップ | その色の線が消える |

- 指が速く動いてマスを飛ばしても、試作と同じく1マスずつたどって伸ばす。
- 右の円のとなりのマスに着いたら、そこでつながって止まる(通り抜けはできない)。
- **なぞっているあいだに画面が動かない**：遊ぶ画面は動かない作り(共通の枠)のうえ、盤面は指の動きで画面を動かさない指定にし、指を盤面がつかまえる(pointer capture)。よつつじは震えない(触感用のスイッチがない)ので、つかまえても困らない。
- **触感**：なぞる操作なので震えない。
- 確認・ルールの画面・クリアの帯が出ているあいだは、盤面が受け付けない(共通の枠のまま)。

### 「1手」の数え方(質問1)
- **案(おすすめ)**：指を置いてから離すまでの1回のなぞりを1手とする。左の円をタップして線を消すのも1手。
  - 「1手戻す」は、そのなぞりの前の状態に戻す(試作と同じ)。
  - 「最初から」は全部の線を消す(戻せない。ほかのパズルと同じ)。

## 7. ヒント

- **戻し方**：答えは1つに決まっているので、色ごとに「自分の線のうち、答えの線と最初から同じ所」だけを残し、それより先(間違って伸ばした所)を戻す。答えとちがう右の円につないだ線も、ちがってくる所から先を戻す。
- **光らせるもの**(質問2)
  - **案(おすすめ)**：まだ答えまで伸びていない線を1本選び(上の円から順)、その線が次に進むマスを1つ、その線の色の点線で点滅させる。線がまだないときは、左の円も一緒に点滅させる。答えそのもの(線)は引かない。
- **一言**(質問3。よつつじに合う言い方の案)
  - 戻したとき：「2本戻しました。光っている所までなぞってみよう」(戻した数は、短くした・消した線の本数)
  - 戻すものがないとき：「光っている所までなぞってみよう」
- 光りは、次になぞるか、1手戻す・最初からを押すと消える。ヒントで戻した線は「1手戻す」では戻らない(ほかと同じ)。

## 8. 音(質問4)

- **案(おすすめ)**
  - なぞって線が伸びているあいだ：鳴らさない(1マスごとに鳴ると、うるさいため)。
  - 線が右の円につながったとき：「コトッ」(置く・引くときと同じ音)。
  - 左の円をタップして線を消したとき：ボタンと同じ軽い「カタッ」。
  - 交差マスで2色がそろって色が混ざったとき：鳴らさない(つながったときの音と重なるため)。
  - 全部の線をつないだのに、空いたマスがある・通っていない色マスがあるとき：間違いの音(低いコトコト)と一言(質問5)。
  - クリア：共通の枠のクリアの音。

## 9. クリア

- 全色の線をつなぎ、色マスを全部通して、空白を残さず全マスを埋めたらクリア。
- 線が光る(試作と同じく、線が少し太くなって戻る動きに、明るくなる動きを足す。約0.7秒)。そのあと共通の枠が「クリア。」の帯を出す。

## 10. 仮パズルを消す

- `public/js/puzzles/trial/` と、その見た目(css の仮パズルの所)を消す。のびしろのヒントの点滅が使っている動き(`blink`)は残す。
- 登録表・オフライン用の一覧から仮パズルを消す。

## 11. 作る順番

1. `logic.js`(試作の問題作りと探し方を移す・難易度表・答えが1つでないときは作り直す・ヒント)と、その自動の確かめ。
2. `worker.js` と、裏側で作って先に作っておく仕組み。
3. `yotsutsuji.js`：盤面の絵、なぞる、左の円のタップ、交差マス、ヒントの光、クリアの光り方、音。
4. 登録表を本物に替え、仮パズルを消し、sw.js の一覧を直す。
5. PCで確かめ、GitHub の main に送る。iPhoneで確かめる。

## 15. 直し：なぞる音を柔らかくする(案2に決めた)

- なぞっているあいだの小さい「コッ」を、もっと耳に柔らかい音にする。音の高さを下げ、高い響きを削って(こもった木の音)、音量も下げる。立ち上がりも少しゆるやかにする。
- つながったときの「コトッ」や、ほかのパズルの音は変えない。
- 聞き比べられるように、低さと小ささを少しずつ変えた3案を作った(public/js/core/sound.js の `STEP_VARIANTS`)。

| 案 | 高さ | 音量 | 長さ | こもり具合(これより高い響きを削る) |
| --- | --- | --- | --- | --- |
| なぞる音1 | 420Hz | 0.10 | 0.05秒 | 1300Hz |
| なぞる音2 | 330Hz | 0.075 | 0.06秒 | 950Hz |
| なぞる音3 | 260Hz | 0.055 | 0.07秒 | 700Hz |

(もとの音は 640Hz・0.16・0.035秒で、高い響きを削っていなかった)

- 設定画面のいちばん下に、一時的に「よつつじのなぞる音(聞き比べ用)」と「なぞる音1・2・3」のボタンを置いた。押すと、その案に切り替わり、なぞるときのように3回続けて鳴る。選んだ案は、よつつじでなぞるときにも使われる(はじめは2)。
- iPhoneで聞いて選んだら、選んだ案だけを残し、聞き比べ用のボタンと、ほかの2案を消す。
- **創が案2(330Hz・音量0.075・0.06秒・950Hzより上を削る)に決めた。** 案2だけを残し、聞き比べ用のボタンは消した。

## 16. 直し：ほかの音も柔らかくする(聞き比べ中)

- ほかの音も全体的にとがって聞こえるので、柔らかくする。なぞる音の案2と同じ考え方で、音の高さを下げてこもった木の音にし、音量も下げる。
- 「カッ」という高い弾き(当たった瞬間のこすれ)を減らし、鳴り始めをゆるやかにして、音の頭を丸くする。
- 4つの音に、それぞれ3案を作った(public/js/core/sound.js の `SOUND_VARIANTS`)。1がいちばん今に近く、3がいちばん柔らかい。
  - **置く・引く音(コトッ)**：のびしろで置く、まじきりで線を引く、うつしえで置く、よつつじでつながる
  - **ボタンの音(カタッ)**
  - **間違いの音(低いコトコト)**：2回たたく。2回目は少し低く、少し小さく、少し長く
  - **クリアの音(木琴のように3つ上がる)**：ド・ミ・ソの間隔で3つ
