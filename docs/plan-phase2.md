# フェーズ2(まじきり)の計画

創の確認ずみ。質問への答えは、いちばん下の「11. 質問への答え」にまとめた。答えと本文が食い違うところは、答えのほうに従う。

## 目的

フェーズ1で作った共通の枠に、まじきりの本物を差し込む。ほかの3つ(のびしろ・よつつじ・うつしえ)は仮パズルのまま。仕様は docs/plan.md の「まじきり」の節に従い、操作と問題の作り方は試作B(docs/prototypes/majikiri.html)を土台にする。試作の●の上限(41〜で4個、81〜で5個)は古いので使わない。

## 1. ファイル

```
public/js/puzzles/majikiri/
├─ logic.js      画面を持たない計算(難易度表・問題作り・部屋の数え方・赤くする部屋・ヒントの線)
└─ majikiri.js   盤面の表示と操作(タップ・はらう・線が伸びる動き・ヒントの光・クリアの光り方)
public/css/screens.css   まじきりの盤面・●・線・組み合わせの見た目を足す
public/js/puzzles/registry.js   まじきりの game を仮パズルから本物に替える
public/sw.js     オフライン用の一覧に2つのファイルを足す
tests/majikiri.test.mjs   問題作りと判定の確かめ
```

`logic.js` は画面に触らないので、`node --test` でそのまま確かめられる。

## 2. 難易度表(docs/plan.md どおり)

| ステージ | 盤面 | 線の本数 | 1部屋の●の上限 |
| --- | --- | --- | --- |
| 1〜20 | 5×5 | 縦1・横1 | 3個 |
| 21〜40 | 6×6 | 縦1・横2 か 縦2・横1 | 4個 |
| 41〜60 | 6×6 | 縦2・横2 | 5個 |
| 61〜80 | 7×7 | 縦2・横2 か 縦1・横3 か 縦3・横1 | 5個 |
| 81〜100 | 7×7 | 縦2・横3 か 縦3・横2 | 5個 |
| 101〜 | 8×8 | 縦3・横3 か 縦2・横4 か 縦4・横2 | 5個 |

- 「か」がある段階では、ステージごとに順番に入れ替える(試作と同じく、2通りならステージ番号の偶数・奇数、3通りなら3つで1周)。
- 段階は共通の `tierOf()`(public/js/core/stages.js)で決める。

## 3. 問題の作り方(試作Bと同じ考え方)

1. 縦線・横線の引き方を全部並べ、乱数(枠から渡される `ctx.rng`。同じステージ番号ならいつも同じ)で答えの線を1つ選ぶ。
2. 分かれた各部屋に、●を1個〜上限の数(部屋のマスの数が上限より少なければマスの数まで)ランダムに置く。
3. 次の問題は捨てて、1からやり直す：
   - 組み合わせに、その段階の上限の数が1つも入っていない(試作では途中からゆるめていたが、計画書どおり必ず入れる)
   - 全部の部屋が同じ数
4. 線の引き方を全部試し、組み合わせ(部屋ごとの●の数を小さい順に並べたもの)が合う引き方が答えの1つだけなら採用する(8×8でも約1,200通り)。
- 何回やり直しても見つからないことがないか、ステージ1〜300を自動の確かめで全部作ってみて確かめる。1問を作る時間も測る(目安：PCで0.1秒以内)。

## 4. 画面

### 上の情報(共通の枠)
- 盤面の中身：`5×5・縦1本・横1本`(describe)
- 進み具合：`縦あと1本・横あと1本`(試作と同じ。引くたびに減る)
- ヒント残り(枠が出す)

### 組み合わせ(盤面の上 `ctx.top`)
- 部屋ごとの●の数を、小さい順に丸い札で並べる。札の中に●をその数だけ描く(試作と同じ)。どの部屋が何個かは出さない。

### 盤面
- 白い正方形にマス目のうすい線。●のあるマスに●を描く。
- 引いた線は、境目に端から端まで描く。タップ・はらい始めた所から両端へスーッと伸びる(約0.18秒。動きを減らす設定では伸びずに出る)。
- 線をすべて引いたら(縦も横も残り0本)、組み合わせより多く出てきた数の部屋の●を全部赤くする(試作の `badKeys` と同じ数え方)。1手戻すと赤は消える。

### ルール説明の文(docs/plan.md どおり)
- 引きたい境目の近くをタップすると、端から端まで直線が引ける。マスの左右のふちの近くなら縦線、上下のふちの近くなら横線。
- 指を上下にはらうと縦線、左右にはらうと横線が引ける。
- 引いた線は消せない。1手戻す・最初からで直す。
- 決まった本数の縦線と横線で、部屋の●の数が上の組み合わせとぴったり同じになるように分けたらクリア。

## 5. 操作

- **タップ**：触れた所から、いちばん近い縦の境目といちばん近い横の境目までの距離を比べ、近いほうの線を引く(試作と同じ)。
- **はらう**：指がマスの3分の1以上動いたら「はらった」と見なす。上下にはらえば縦線、左右にはらえば横線を、はらい始めた所にいちばん近い境目に引く。
- 同じ所にもう線があるときは何もしない。その向きの線をもう引き終えていたら「縦線はもう引けない。」「横線はもう引けない。」と出す。
- タップとはらうの区別は、どちらも「マスの3分の1」を境にする。
- 音：線を引いたとき「コトッ」(はらうときも)。

### 触感(タップで線を引いたときだけ)
- 盤面の各マスに、共通の `ctx.tapCell` をつける。タップの判定と触感はこれに任せる。
  - `buzz` は「このタップで線が引けるか」を答える(もう引けない、もうある線なら震えない)。
  - はらうときは震えない(指が3分の1以上動くと、共通部分がスイッチを止める)。
- はらう操作は、まじきりが盤面で指の動きを見て判定する。
- **共通部分の小さな直し**(public/js/core/haptics.js)：
  - `buzz(e)` にタップした所(指の位置)を渡す(まじきりは、位置で引く線が変わるため)。
  - `moveLimit`(タップと見なす動きの上限)に、数のほか「その場で計算する関数」も渡せるようにする(マスの大きさは画面で変わるため)。
- **気をつけること**：盤面が指をつかまえる仕組み(pointer capture)を使うと、iPhoneでスイッチが押されず震えなくなるので使わない。指の動きは window で受ける。

## 6. ヒント

- 正しい答えにない線(=間違った線)を全部戻してから、まだ引いていない正しい線を1本、点線で点滅させる(試作と同じ。横線を先に、上・左から順に選ぶ)。
- 一言：「2手戻しました。光っている所に引いてみよう」(戻すものがなければ「光っている所に引いてみよう」)。のびしろの形にそろえた(質問5)。
- 回数の数え方、使い切ったら「このステージを飛ばす」は共通の枠のまま。
- 光っている線は、次に線を引くか、1手戻す・最初からを押すと消える。

## 7. クリア

- 決まった本数を全部引いて、組み合わせがぴったり合ったらクリア。
- どの部屋の●も、いっせいに光る(少し大きくなって戻る。約0.7秒)。そのあと共通の枠が「クリア。」の帯を出す。

## 8. 作る順番

1. `logic.js`(難易度表・問題作り・判定)と、その自動の確かめ。
2. 共通部分の小さな直し(`buzz(e)`・`moveLimit` に関数)。今の確かめが通ることも見る。
3. `majikiri.js`：表示、タップ・はらう、線が伸びる動き、赤い●、ヒント、クリアの光り方。
4. 登録表を本物に替え、sw.js の一覧に足す。
5. PCで確かめ、GitHub の main に送る。iPhoneで確かめる。

## 9. 動作確認

### 自動の確かめ(`node --test`)
- 難易度表：ステージ 1・20・21・22・41・61・62・63・81・82・101・102・103 で、盤面・線の本数・上限が表どおり。
- ステージ1〜300の問題がすべて：答えがちょうど1つ、上限の数が組み合わせに入っている、全部同じ数でない、どの部屋も●が1個〜上限。
- 同じステージ番号なら同じ問題になる。
- 赤くする部屋：組み合わせ1・1・2・3で、できた部屋が1・2・2・2なら「2」の3部屋が赤(計画書の例)。
- ヒント：間違った線を除き、答えの線を1本返す。

### PC(Chrome)
1. `npx serve public` を動かし、表示されたアドレスを開く。開発者ツールでスマホの大きさにする。
2. まじきりを開き、上の組み合わせと「5×5・縦1本・横1本」「縦あと1本・横あと1本」を見る。
3. 境目の近くをクリック → 近いほうの線が、押した所から両端へ伸びる。
4. マウスで上下・左右に引っぱって離す → はらった向きの線が引ける。
5. 縦線を引き終えたあとにもう一度縦線を引こうとする →「縦線はもう引けない。」
6. 合わない引き方で全部引く → 多く出てきた数の部屋の●が赤くなる。1手戻すと消える。
7. ヒント → 間違った線が消え、点線が点滅する。3回で「このステージを飛ばす」。
8. 正しく引く → ●がいっせいに光り、「クリア。」の帯。◀▶・一覧で21・41・61・81・101あたりに進み、盤面と本数が変わるのを見る(一覧は遊べる所までしか出ないので、これは自動の確かめで見る)。

### iPhone(1台)
1. ホーム画面のアプリを一度完全に閉じてから開く(新しい版に入れ替わる)。
2. まじきりを開く。組み合わせの札と●が見えるか。
3. 境目の近くをタップ → 線がスーッと伸び、「コトッ」と鳴って軽く震える。
4. 指で上下・左右にはらう → 線が引ける。鳴るが、震えない。
5. もう引けない向きの線をタップ → 一言が出る。震えない。
6. 合わない引き方で全部引く → ●が赤くなる。
7. ヒントを押す → 間違った線が消え、点線が光る。
8. 正しく引いてクリア → ●がいっせいに光り、帯が出る。
9. 暗い画面でも、●・赤い●・線が見分けられるか。
10. 盤面の上で指を動かしても、画面がずれたり拡大したりしないか。

## 10. 質問

1. **配色の使い方**：計画書では「どのパズルも、くすみ系5種類の配色をステージごとに切り替える」とあるが、まじきりで何に色をつけるかは決まっていない。
   - 案A(おすすめ)：引いた線を、引いた順に、その回の8色で1本ずつ色を変える。●はうすい灰色のまま(赤い●と見分けやすい)。
   - 案B：線は1色(落ち着いた緑)のまま。クリアのとき、部屋ごとにその回の8色でうすく塗る。
   - 案C：ほかの案があれば。
2. **組み合わせの見出し**：試作には組み合わせの上に「この組み合わせの部屋に分ける」という一言がある。計画書には書いていない。残すか、消すか。
3. **間違いの音**：「間違いのとき」に鳴らす音(低いコトコト)を、どの場面で鳴らすか。
   - おすすめ：「縦線(横線)はもう引けない。」のときと、全部引いて●が赤くなったとき。もう線がある所を押したときは鳴らさない。
4. **●が赤くなったときの一言**：試作には一言がない。のびしろの「埋まりきらなかった。1手戻してみよう」に合わせて「数が合わない部屋がある。1手戻してみよう」などを出すか、何も出さないか。
5. **ヒントの一言**：「2手戻しました。光っている所に引いてみよう」でよいか(試作は「間違った線を2本消した。点線の所をタップする。」)。
6. **進み具合の表示**：「縦あと1本・横あと1本」でよいか。
