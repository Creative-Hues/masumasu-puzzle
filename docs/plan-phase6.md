## 2. 最初の画面の小さな絵(解いている途中の盤面)

- 4つのカードそれぞれの右側に、そのパズルの「解いている途中の盤面」の小さな絵を出す。
- 絵の中身(質問4)：
  - 案(おすすめ)：パズルごとに決まった見本の盤面を1つ用意し、答えの半分くらいまで進めた所を描く。
    - のびしろ：5×5で、2個置いて色が伸びた所(番号つき)。
    - まじきり：5×5で、●と、線が1本引いてある所。
    - よつつじ：5×5で、1本はつながり、もう1本は途中の所。
    - うつしえ：横に2つで、ピースがいくつか映った所。
  - 見本の盤面は、それぞれのステージ1の問題から作った値を、コードにそのまま書いておく(開くたびに問題を作らないので、すぐ出て、オフラインでも同じ)。
- 描き方：小さな図(SVG。拡大してもぼやけない絵の書き方)で描く。色の決まり(1-9)を使うので、明るい・暗いに自動で合う。デザインは1で決めた値にそろえる。
- 大きさ(質問5)：カードの高さに合わせて、縦横約64px。カードの文字(名前・ひとこと説明)は左、絵は右。
- 絵の配色：その回の配色のうち、どれを使うか(質問6)。
- 絵はタップの邪魔をしない(カード全体を押すと、そのパズルが開く。今のまま)。

## 3. 進み具合の書き出し・読み込み

### 何を書き出すか
- 端末に保存しているもの全部：4つのパズルの進み具合(どこまでクリアしたか・今のステージ・飛ばしたステージ)、設定(効果音・音量・触感・画面の明るさ)、ルールを出したパズル(質問7)。
- 書き出す形：文字だけのファイル(JSON。中身を文字で書いたデータ)。名前は「ますます-バックアップ-2026-11-05.json」のように日付をつける。
- 中に「ますますのバックアップであること」と、保存の形の版の番号、書き出した日を入れ、ちがうファイルを読み込まないようにする。

### 画面
- 設定画面のいちばん下に「バックアップ」を足し、「書き出す」「読み込む」の2つのボタンを置く。
- **書き出す**：
  - iPhone：共有の画面(AirDrop・メール・「ファイル」に保存など)を出す。新しいiPhoneへは、AirDropか、「ファイル」(iCloud Drive)に保存して渡す(質問8)。
  - PCなど共有の画面がない所：ファイルとしてダウンロードする。
- **読み込む**：ファイルを選ぶ画面を出す。選んだら、中身を確かめてから「今の進み具合を、読み込んだもので置き換えますか。」と画面の中で一度聞く(飛ばすの確認と同じ形)。「置き換える」で置き換え、最初の画面に戻る。
  - ますますのファイルでないとき・壊れているとき：「読み込めませんでした。」と出し、今の進み具合は変えない。
  - 置き換え方(質問9)：おすすめは「全部置き換える」(わかりやすい)。
- 保存の仕組み(public/js/core/storage.js)に「書き出す中身を作る」「読み込んだ中身を確かめて置き換える」を足す。確かめは、今ある「どんな中身でも使える形に直す」仕組み(normalize)を使う。

### 自動の確かめ
- 書き出したものを読み込むと、元と同じ進み具合・設定になる。
- ちがうファイル・壊れたファイル・古い版のファイルを読み込んでも、止まらない(古い版は読める、ちがう・壊れたものは断る)。

## 5. 全体の動作確認

### PC(Chrome)
1. `node --test` が全部通る。
2. `npx serve public` を動かし、開発者ツールでスマホの大きさ(375×667 と 390×844)にする。
3. 最初の画面：4つのカードに、名前・ひとこと説明・小さな絵。明るい・暗いの両方で見る。
4. 4つとも：初めて開くとルールが出る。◀▶・一覧・ヒント3回で「飛ばす」・確認・クリアの帯・「次へ」。1画面に収まる。
5. 4つの盤面を明るい・暗いで写真に撮り、並べて、そろえた値になっているか見る。
6. 設定：効果音・音量(つまみ・離すと置く音)・触感・画面の明るさ。
7. 書き出し：ファイルができる。中身にますますの印・日付・進み具合がある。
8. 読み込み：何ステージか進めてから、さっきのファイルを読み込む → 確認が出て、置き換えると書き出したときの進み具合に戻る。ちがうファイルを選ぶと「読み込めませんでした。」。
9. 通信を切って再読み込みし、4つとも遊べる。

### iPhone(1台)
1. ホーム画面のアプリを一度完全に閉じてから開く。最初の画面の4つのカードに小さな絵が出る。暗い画面でも見やすい。
2. 4つとも遊ぶ：触感(まじきりのタップ・のびしろの置く)、音(置く・なぞる・ボタン・間違い・クリア)、ヒント・飛ばす・クリアの帯。デザインがそろって見えるか。
3. 設定の音量のつまみで、4つとも音の大きさが変わる。効果音オフで鳴らない。
4. **書き出し**：設定 → 「書き出す」 → 共有の画面で「"ファイル"に保存」を選ぶ。
5. **読み込み(1台で引っ越しの代わりに確かめる)**：どれかのパズルを1〜2ステージ進める → 設定 → 「読み込む」 → さっき保存したファイルを選ぶ → 確認で「置き換える」 → 進み具合が書き出したときに戻る。
6. 写真など、ますますでないファイルを選ぶと「読み込めませんでした。」と出て、進み具合は変わらない。
7. アプリを完全に閉じて開き直し、進み具合と設定が残っている。
8. 機内モードで開き直し、4つとも遊べる。

## 6. 質問

1. **盤面の地とマスの色**：今は、のびしろだけ「灰色の地に白いマス」、ほかは「白い札に灰色のマス(まじきりは白いマスを線で区切る)」になっている。
   - 案A(おすすめ)：全部「白い札(角の丸み12px)に、うすい灰色のマス(角の丸み16%・すき間10%)」にそろえる。暗い画面のマスは、札より少し明るい色にする。
   - 案B：全部「灰色の地に白いマス」(今ののびしろの形)にそろえる。
2. **まじきりのマス目**：まじきりは、線を「マスの境目」に引くので、今は0.5pxの線でマスを区切っている。
   - 案A(おすすめ)：ほかと同じく、すき間で区切る(線はすき間の上に引く)。
   - 案B：まじきりだけ、マス目の線のままにする。
3. **ヒントの点線の色**：案A(どれも落ち着いた緑)、案B(よつつじ・うつしえはその線・ピースの色、のびしろ・まじきりは緑。今のまま)のどちらにするか。おすすめは案B(どの線・どのピースのヒントかが、色でわかる)。
4. **小さな絵の中身**：決まった見本の盤面を、答えの半分くらいまで進めた所を描く(おすすめ)か、ほかの案(今のステージの問題を描くなど)にするか。今のステージを描くと、開くたびに問題を作るので、最初の画面が少し遅くなる。
5. **小さな絵の大きさと場所**：カードの右側に約64pxでよいか。
6. **小さな絵の配色**：配色5種類のうち、いつも1つ目(秋の山)を使う(おすすめ。見た目が毎回同じ)か、それぞれのパズルの今のステージの配色にするか。
7. **書き出す中身**：進み具合だけでなく、設定(効果音・音量・触感・画面の明るさ)と、ルールを出したかどうかも一緒に書き出してよいか(おすすめ。新しいiPhoneでも同じになる)。
8. **書き出しの渡し方**：iPhoneでは共有の画面を出す(AirDrop・「ファイル」・メールなどから選ぶ)でよいか。ほかに、文字の「引っ越しの合言葉」をコピーして、メモやLINEで送る形もできる(ファイルを使わなくてすむが、長い文字になる)。
9. **読み込むときの置き換え方**：全部置き換える(おすすめ。わかりやすい)か、パズルごとに進んでいるほうを残す(まちがえて古いファイルを読んでも進み具合が減らない)か。

## 8. 作ったこと(実装のあと)

- **デザイン**：決まった値を base.css の「盤面のデザインの決まり」にまとめた。絵(canvas・SVG)で描くよつつじ・うつしえ・小さな絵は public/js/ui/look.js から同じ値を読む。暗い画面のマスは #2e3431(地 #1a1d1c より明るい)。
  - うすい色は「地の色(--bg)へ45%」なので、暗い画面では、明るい画面よりも落ち着いた色になる。
  - 見比べの画面写真：docs/design/board-compare.png(4つ × 明るい・暗い)。
- **小さな絵**：public/js/ui/thumbs.js。4つの見本の盤面を、アイコンの4色で描く(のびしろ・よつつじの2色は、見分けやすいようにピンク #b5838d と青灰色 #8e9aaf にした。まじきりの線は #e5989b)。
- **書き出し・読み込み**：public/js/core/storage.js(`exportBackup`・`parseBackup`・`replaceWith`)と設定画面の「バックアップ」。ファイル名は「ますます-バックアップ-年-月-日.json」。
